3.1

An Interactive Animated Story

Two characters, one backdrop, perfect timing.

go to · glide · broadcast

The stage director's cue

when ⚑ clicked
go to x: -200 y: -100
glide 2 secs to x: 0 y: -100
say Hi Bear! for 2 seconds
broadcast your turn
when I receive your turn
say Hi Cat! Nice day! for 2 seconds
  • go to teleports · glide slides
  • A broadcast is an invisible shout that any sprite can hear
Lab · 10 min

A conversation that plays itself

  • Cat (flag): say a line → broadcast line 2
  • Bear (receive line 2): reply → broadcast line 3
  • Cat (receive line 3): reply → broadcast line 4
  • Both (receive line 4): glide off together
WATCH Only line 1 starts with the green flag. Everything else starts with "when I receive."
3.2

A Simple Game with Variables & Score

Meet the variable, a box that remembers.

A variable is a whiteboard

SCORE: 0 1 2

set score to 0
change score by 1
score
  • set = erase and write
  • change = add to what's there
  • Tick the checkbox to show it on stage
GAME PLAN Apple falls from a random x → touching the cat? +1 → back to the top.
Two scripts, one game

The apple and the catcher

when ⚑ clicked
set score to 0
forever
go to x: pick random -200 to 200 y: 170
repeat until touching Cat?
change y by -8
if y position < -170 then
go to x: pick random -200 to 200 y: 170
change score by 1
when ⚑ clicked
forever
go to x: mouse x y: -140
WHY NOT "touching edge?" At y: 170 the apple already touches the top edge, so it would never fall.

Catch the Apple

  • Add an Apple · make score (For all sprites) · tick its box
  • Build the Apple script, then the Cat script
  • Play it, then save it: File → Save to your computer
  • Fast finishers: a 30-second time left timer
WATCH The +1 goes below the repeat-until, not inside it.
3.3

Debugging & Remixing

Bugs aren't the enemy. They're the job.

The 4-step method

Watch → Predict → Change ONE thing → Test

  • 1 Watch what actually happens
  • 2 Predict which block causes it
  • 3 Change ONE thing
  • 4 Test. Still wrong? Go round again.
  • Click one block to run it
  • Tick a variable's checkbox
  • Temporary say (score)
  • See Inside any shared project
REFRAME Not "it's broken," but "interesting, let's find out why."
The usual suspects

90% of Scratch bugs

  • Nothing happens → code is on the wrong sprite
  • Runs once, never again → an if with no loop
  • Blocks never run → trapped below a forever
  • Score jumps by many → condition stays true for many frames
  • Sprites out of sync → use broadcasts, not waits
Lab · 17 min · debugging buddies

The Bug Hunt: 4 bugs hidden

  • Open l3-3-bug-hunt-starter.sb3
  • Driver holds the mouse
  • Navigator asks and writes
  • Swap after every bug
  • What did you expect?
  • What happened instead?
  • Which block is responsible?
  • One change to test it?
TIP Move the mouse every way, watch the apple, miss on purpose, press the flag twice.
Teach-It role-plays · kid cards

Three coaching moves

  • Maya, 6 · "Let's be the characters first! You be the bear…" (story before code)
  • Theo, 10 · "Tell me your game like you're explaining it to a friend." (design first)
  • Priya, 9 · "Walk me through it like I know nothing." (ask, don't fix)
WATCH The biggest parent mistake is grabbing the mouse. Sit on your hands.
After the hunt · debrief

The four bugs we squashed

  • Cat used mouse y → needs mouse x
  • No set score to 0 → the score carried over
  • change y by 8 → the apple never fell (needs -8)
  • change score by 1 inside the falling loop → move it below
