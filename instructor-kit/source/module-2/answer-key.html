2.1 · Sequences & Timing

Q1
What is a "sequence" in coding?
A) Steps carried out in order, one after another
Why: steps run top to bottom, exactly as stacked. B is wrong because order is exact, not random. C describes a loop (Lesson 2.2).
Q2
Which category holds the wait block?
B) Control (orange)
Why: wait (1) seconds is the first block in Control. Blue is Motion; purple is Looks.
Q3
Your child's cat "freezes" for two seconds mid-routine. Most likely reason?
B) A "say for 2 seconds" or "wait" block is holding, as designed
Why: the block is doing its job. Point at the words "for 2 seconds." Adults who pick A are voicing the fear of breaking the computer. Reassure them and move on.
Q4
say Hello! for 2 seconds vs plain say Hello!?
B) The timed one pauses the script before the next block; plain say moves straight on
Why: the timed version shows the bubble, waits, removes it, then continues. Plain say leaves the bubble up and runs the next block at once. For step-by-step scenes, use the timed one.
Lab solution — Greeting Routine

Reference: labs/module-2/l2-1-greeting-routine.sb3. One script on the cat sprite:

when ⚑ clicked
go to x: 0 y: 0
say Hi, I'm Scratchy! for 2 seconds
wait 1 seconds
move 120 steps
say Welcome to my world! for 2 seconds

Challenge version: start sound (Meow) and next costume go between the wait and the move.

Common wrong turns & coaching: (1) No go to x: 0 y: 0. The cat starts wherever the last run left it and eventually walks off-stage. Ask: "Where does the cat start the second time?" (2) Plain say instead of say-for-seconds. Both bubbles flash by, or the first is instantly replaced. Ask them to read the two block labels aloud. (3) A block not snapped. It sits a few pixels away and never runs. Drag the stack by its hat block; anything left behind isn't attached. (4) Two green-flag scripts. An old S1 script also runs, so the cat does two things at once. Right-click the code area → Clean up Blocks to find strays.

2.2 · Loops — Making Things Repeat

Q1
You want the cat to blink exactly 5 times. Best loop?
A) repeat 5
Why: you know the count. forever would never stop, and wait 5 seconds is a pause, not a loop.
Q2
Only which blocks repeat in a loop?
B) Only the blocks inside the C-shape
Why: blocks nested in the loop's "mouth" repeat. Blocks above or below it run once. Block color has nothing to do with it.
Q3
A block placed after a "forever" loop will…
A) never run
Why: the program never gets past forever. Scratch hints at this: forever has no notch on its bottom, so nothing can snap below it.
Q4
The walking cat zooms across in a blink. Best first fix?
A) Add (or lengthen) a wait inside the loop
Why: the wait has to repeat with each step to slow every step. A wait after the loop only pauses once, at the end. Try 0.1–0.3.
Lab solution — A Real Walking Cat

Reference: labs/module-2/l2-2-walking-cat.sb3. One script on the cat sprite (which has two costumes):

when ⚑ clicked
go to x: -200 y: 0
repeat 20
move 20 steps
next costume
wait 0.1 seconds

Challenge (patrol) version. Wrapping the original repeat inside a forever works too; this is the tidier form:

when ⚑ clicked
set rotation style left-right
go to x: -200 y: 0
forever
move 20 steps
if on edge, bounce
next costume
wait 0.1 seconds

Common wrong turns & coaching: (1) next costume below the loop. The cat glides with frozen legs. Ask: "Is the costume change inside the mouth, or outside?" (2) No wait inside. The cat teleports across. (3) Upside-down cat in the challenge. Add set rotation style [left-right]. (4) A second forever script keeps running after the challenge. The red stop ends it. Delete the leftover.

2.3 · Conditionals & Sensing — Making Choices

Q1
What shape of block fits in an "if ___ then" slot?
A) A hexagon (true/false) block
Why: the slot is pointy and takes only true/false conditions, such as touching (edge)? or key (space) pressed?. Oval reporters give values and won't fit. Hat blocks only start scripts.
Q2
Why do most games wrap their "if" checks in a forever loop?
B) So the condition is checked constantly, not just once
Why: without the loop Scratch checks once, when the script starts, and never again. Tie it back to the warm-up: you check for rain all day, not once.
Q3
"if/then/else" is best when…
B) you want one thing if true and a different thing otherwise
Why: use else when the outcomes are opposites of the same question. The four arrow keys are separate questions, so they get four separate ifs.
Q4
Script matches the example but the cat won't move. Try first?
A) Click the stage once so it has keyboard focus
Why: key presses go to whatever part of the page was clicked last. Click the stage, then check the nesting (change → inside if → inside forever). Restarting is never the first move.
Lab solution — Drive the Cat with Arrow Keys

Reference: labs/module-2/l2-3-arrow-key-cat.sb3. One script on the cat sprite:

when ⚑ clicked
forever
if key right arrow pressed? then
change x by 10
if key left arrow pressed? then
change x by -10
if key up arrow pressed? then
change y by 10
if key down arrow pressed? then
change y by -10

Challenge: a fifth if inside the same forever, if <touching (edge)?> then say (Ouch!) for (1) seconds. (While the bubble shows, the other keys pause, which is fine at this stage.)

Common wrong turns & coaching: (1) if outside the forever. The keys work for a split second at the start, then never again. Ask: "How often does it check?" (2) x and y swapped. Up moves the cat sideways. Say: "x is across, like a crossword; y is up and down." (3) Wrong sign. Left and down need −10. (4) when [right arrow] key pressed hat blocks instead of the loop. That also works but moves jerkily because of the keyboard-repeat delay. Accept it, then show the smoother loop version. (5) No keyboard focus. Click the stage.
