Module 4 — Leveling Up: Bigger Projects

How to teach clones and My Blocks to the grown-ups in Session 4, then run Session 5, Family Build Night, where parent-and-child pairs plan and build Star Catcher together, from a paper design card to a launch-day showcase.

4 lessons ~4 hrs teaching (2 sessions) Lessons 4.1–4.4 Level Beginner Maps to Session S4 + S5

How to Use This Guide

  • This module runs over two sessions with very different rooms. S4 is adults only and follows the usual rhythm: Frame → Teach → Lab → Teach-It role-play → Check. S5 is Family Build Night: children attend, and you mostly stop teaching and start running a room.
  • Read the two run-sheets first. S5 needs setup the day before (devices, rescue file, printed posters, name tags), so plan it at the end of S4, not the morning of S5.
  • Build both reference games yourself before S4, including the rescue file labs/module-4/l4-3-star-catcher-part1.sb3. You will demo from them and load them onto devices.
  • Teal = hands-on, amber = watch-outs. Say: boxes are lines you can read out loud as written.
  • Half-day format: in the three-Saturday version, S3 + S4 share Day 2, and S5 + S6 share Day 3. Invite the children for the Day 3 morning only (S5), and send them home before Module 5.
The through-line

Everything in S4 is a part for S5. The falling stars from 4.1 become Star Catcher's star factory; the reset game block from 4.2 becomes the Bowl's setup. Tell the adults this at minute one: "Tonight you learn the parts. Next time you build the machine, with your child as the boss." Seeing the destination makes the abstract ideas (clones especially) worth the struggle.

Session Run-Sheet — S5 Family Build Night

Room setup (before doors open — allow 45 min)
  • One device per family, each with a mouse, the Scratch editor open to a new project, and volume at about 30%. Label each table with a family name. Two chairs side by side, child's chair in front of the mouse.
  • Rescue file on every device: copy l4-3-star-catcher-part1.sb3 to the desktop (or a Rescue folder) and test that File → Load from your computer finds it. Keep a USB stick with both Module 4 files as backup. Put l4-4-star-catcher-final.sb3 only on your machine.
  • Name tags: child tags say the name big plus DIRECTOR; adult tags say TYPIST. Kids love the titles, and the tags make the rules visible from across the room.
  • Wall poster (large print, at kid eye level, next to the screen): "The Director decides. The Typist types only when the Director says 'your turn.' The Director presses every green flag." Add a second poster: Someday List, with sticky notes for parked ideas.
  • Projector with the slide deck on the Family Build Night title slide. A spare stack of printed blank Game Design Cards and pencils/crayons. A timer you can show on screen.
  • Snack table away from the devices (ask about allergies on the RSVP). A "quiet corner" with paper and crayons for a tired or overwhelmed child, or a younger sibling.

The rescue file protocol (checkpoint, 1:00)

The lesson's times assume a parent alone; with a child driving, expect about double. Some families will be behind at 1:00, and that's planned for. Say to the whole room, not to one family: "If your stars aren't being caught yet, that's fine. Here's a shortcut so you can do the fun part."

1) File → Save to your computer as our-star-catcher-v1 (their work is kept). 2) File → Load from your computer → l4-3-star-catcher-part1.sb3. 3) Let the child re-choose the bowl costume or backdrop right away so it feels like theirs again. 4) Rename it Star Catcher. The rescue file is exactly the end of step 7, so step 8 starts cleanly for everyone.

If a game is broken at 1:45, launch from the last version that worked; the showcase is about the Director explaining their game, not about which steps got finished.

When a participant comes without a child

Expect a few (a sick child, grown children, a grandparent whose grandkids live away). Pair two such adults as director and typist using the 4.3 kid card below, switching roles at the break. Or make them floating playtesters who visit tables after each checkpoint. Never leave them building alone at the back.

Lesson Plans

4.1

Clones — One Sprite, Many Copies

40 min · S4
Objectives
  • Explain a clone with the rubber-stamp idea (original = stamp, clones = prints)
  • Use create clone of myself, when I start as a clone, and delete this clone
  • Build the "hidden original stamps clones in a forever loop" pattern
  • Know what a clone copies (position, costume, size, visibility) and why clones must be deleted (limit ≈ 300)
Teaching sequence
  1. Why one sprite isn't enough (3m). "In 3.2 one apple fell. What if we wanted twenty?" Duplicating 20 sprites means editing 20 times. Clones: write the code once, make copies while the program runs.
  2. The stamp (4m). Hold up a real rubber stamp (or cookie cutter). Press three prints. Demo script: "The stamp stays in my hand. The prints are on the paper. In Scratch the original sprite is the stamp and it usually hides; the clones are the prints."
  3. The three blocks, live (5m). Show them at the very bottom of Control (adults scroll past them). Build the two-script shape: original hide → forever → create clone of myself → wait 1 seconds; clone when I start as a clone → show → say "I'm a copy!" for 2 seconds → delete this clone. Delete the wait briefly to show the flood, then put it back.
  4. The four rules (3m). Clones copy everything, including being hidden (so clones need show); each clone runs its own copy of the clone script; when ⚑ clicked runs only on the original; always clean up (about 300 clones max; the stop sign clears them all). Ask the room: "Is this code running on the stamp, the prints, or both?"
  5. Lab launch (from 15m). Falling stars. Warn them up front: "When you click the flag after the first script, nothing happens. That's correct."
Lab — Falling Stars (17 min)

New project; add the Star sprite and a dark backdrop (Stars or Night City). Original: hide, then forever go to x: (pick random -220 to 220) y: 180 → create clone of myself → wait 1 seconds. Clone: show → repeat until ⟨(y position) < -170⟩ → change y by -5, then delete this clone. Early finishers: random size and color, spinning stars, or snow. Reference: labs/module-4/l4-1-falling-stars.sb3. Everyone saves it: it feeds the capstone.

Circulate for: show missing from the clone script (nothing appears); the falling code under the green flag (the original falls); no go to before stamping (stars clump in one spot); y position dropped in the wrong slot of the < block; until touching edge used instead (each star deletes itself instantly because it's born touching the top).

Teach-It role-play — "Stamps and prints" (6 min)

Pairs: one adult takes the kid card, the other coaches. Coach's goal: let the child discover the invisible-clone bug instead of fixing it. Swap once at 3 minutes.

Kid card — Theo, age 9

Excited and fast. You've just built the stamp script and clicked the flag. Nothing appears, and you say "It's broken! Scratch is broken!" If your coach grabs the mouse, fold your arms. If they ask you a question about the stamp, think out loud and find it yourself. Later, try putting create clone of myself inside the clone script "to get more stars."

Where's the stamp right now? In my hand, not on the paper. So what should each print do after it lands?

We hid the stamp. The prints are copies of the stamp… so what do the prints look like right now?

Who should do the stamping — the stamp or the prints?

Debrief (1 line each): What did it feel like not to fix it? Which question worked?

Watch-outs
  • "I'm lost" fog. Clones are the first time lots happens at once, and adults who kept up easily in Module 3 may freeze. Name it: "Confusion here is your brain stretching. The stamp-and-prints question solves most of it."
  • Can't find the blocks. The clone blocks sit below the loops and ifs at the very bottom of Control; the hat block only peeks in. Show where to scroll.
  • Trackpad drags into the wrong slot. Dropping y position into the < block is fiddly. Mice help; so does zooming the code area (the + magnifier bottom-right).
  • Flood of clones. Someone will remove the wait or stamp from inside the clone script. The red stop sign clears all clones; reassure them nothing is broken.
  • Screen-time guilt surfaces when adults see how absorbing this is. Reframe: making a game is creating, not consuming.
Check — quiz

Answers: clones don't appear because they start hidden like the original and need show (B); the script that runs only on clones is when I start as a clone (C); slowing then stopping = clones never deleted, piling toward the 300 limit (A); create clone inside the clone script = every clone makes another, flooding the screen until the limit (B).

4.2

My Blocks — Make Your Own Blocks

35 min · S4
Objectives
  • Explain why naming a chunk of code helps (write once, change once), the recipe-card idea
  • Use My Blocks → Make a Block, and put steps under the pink define hat
  • Add a number input and drag its oval into the script
  • Build the reset game block used in the capstone
Teaching sequence
  1. The recipe card (2m). "'Make pancakes' stands for crack, whisk, pour, flip. You write the steps once, then just say the name." Programmers call it a function; the kids never need the word.
  2. Make a Block, live (4m). Pink My Blocks circle → Make a Block → type jump → OK. Point at the two things that appear: the new block in the palette and the define jump hat. Under it: repeat 10 → change y by 10, repeat 10 → change y by -10. Call it from when space key pressed and when this sprite clicked. Then change 10 to 15 once: "Both jumps changed."
  3. Screen refresh (1m). Tick Run without screen refresh via right-click → Edit: the cat teleports. Untick it. "Leave this unticked."
  4. Inputs (4m). Make dance + Add an input (number or text) named times + Add a label "times." Demo script: "The pink oval in the define hat holds the number. Drag it out: you get a copy. Don't type the word." Call dance 3 times, then dance 6 times.
  5. Reset game preview (1m). "This one you'll use at Family Build Night." Note that My Blocks belong to one sprite.
Lab — Three Custom Blocks (15 min)

In a new cat project: (1) jump used by two scripts; (2) dance (times) times called with two different numbers; (3) make score and lives variables, then define reset game: set score to 0, set lives to 3, go to x: 0 y: -150, show, called from when ⚑ clicked. Challenge: jump (height) using (height / 10). Reference: labs/module-4/l4-2-my-blocks.sb3.

Circulate for: steps sitting loose instead of snapped under the define hat (block "does nothing"); the word times typed into a slot instead of the oval dragged out; screen refresh ticked; a different sprite selected ("my block vanished").

Teach-It role-play — "New words for the computer" (6 min)

Coach opens with the unplugged "zoomba" game, then helps the child spot a repeat without pointing at it. Swap at 3 minutes.

Kid card — Priya, age 11

Confident and a bit impatient. Your game has the same four blocks copied in three places. When your coach suggests a custom block, say "Copying is faster. Why bother?" Only get interested if they let you name the block (you want to call it "boing"). Later, type the word times into the repeat slot and insist it's right.

I'm going to teach you a new word: zoomba. Zoomba means clap twice and spin around. Ready? Zoomba! Now let's teach the computer a new word.

I see those same blocks twice. What would you call what they do? What if that were one block with that name?

The value lives in this pink oval. Drag it out and see what happens.

Watch-outs
  • "Is this programming now? I'm not a programmer." Some adults hit a wall at the word function. Keep it to the recipe card; don't lecture on terminology.
  • Dragging the input oval needs a precise grab on a small shape. Zoom in, bring a mouse.
  • Variables must exist first. reset game needs score and lives, made For all sprites, as in 3.2.
  • Editing a block (right-click the define hat → Edit) updates every use. Adults worry they "broke" the calls; they didn't.
Check — quiz

Answers: the block's steps go under the pink define block (B); the cat teleports because Run without screen refresh is ticked (A); reset game missing on the Star because custom blocks belong to the sprite they were made in (C); to use an input, drag the pink oval out of the define hat (B).

4.3

Capstone Part 1 — Plan It & Build the Core

45 min · S5 (+ 10 min briefing in S4)
Objectives
  • Plan a game on paper: brainstorm, pick ONE idea, sketch, list the pieces, keep a Someday List
  • Fill in the Game Design Card with a child, in the child's words
  • Build the smallest playable version: bowl moves, stars fall, catching scores
  • Work as director (child) and typist (parent)
Teaching sequence
  1. In S4 (the 15-min briefing). Show the five-step planning loop and the Star Catcher design card. Hand out blank cards: "Fill it in at home with your child. Write their words, not yours." Introduce director/typist and practice the "narrate and hand it back" line in pairs for one minute.
  2. S5, steps 1–2 (≈ 8m). Delete the cat; add Bowl and Star; Stars backdrop. Variables score and lives, For all sprites.
  3. Step 3 (≈ 8m). On the Bowl: define reset game (set score to 0, set lives to 3, go to x: 0 y: -150, show). "Same block as last week."
  4. Step 4 (≈ 8m). Bowl: when ⚑ clicked → reset game → forever with two if key (right/left arrow) pressed? then change x by (10 / -10). "Directors: click the stage, then use the arrows."
  5. Step 5 (≈ 6m). Star factory: hide → wait 1 seconds → forever → create clone of myself → wait (pick random 0.5 to 1.5) seconds.
  6. Step 6 (≈ 7m). Each clone: when I start as a clone → go to x: (pick random -220 to 220) y: 170 → show → forever → change y by -5. Stars pile up at the bottom: "That's a cliffhanger for after the break."
  7. Step 7 (≈ 8m). Add the Pop sound. Inside the forever: if touching Bowl? then → change score by 1 → hide → play sound Pop until done → delete this clone. Explain once: deleting a clone cuts off its sound.
Lab — Star Catcher Part 1 (built live, family pairs)

Steps 1–7 above, paced from the projector. The finish line is the checkpoint: a game that catches stars and keeps score. Rescue file = end of step 7: labs/module-4/l4-3-star-catcher-part1.sb3.

Circulate for: who is holding the mouse (more than any block); variables made "For this sprite only"; the arrow ifs outside the forever; the original Star visible and frozen at the top; reset game placed inside the forever; start sound instead of play sound … until done.

Teach-It — live coaching (and the role-play for adults without a child)

Tonight the role-play is real. Coach the adults, not the kids: crouch beside the parent and whisper a line they can use. Adults without a child pair up with this card.

Kid card — Lily, age 6

Thrilled to be the boss, wants every star purple and the bowl to be a cat. Can press the green flag and choose sprites but struggles to drag. Wants to add "a dragon that eats the stars" in the middle of step 5. After 20 minutes you get wiggly and say "you do it."

You're the boss of this game. I'm your helper. Tell me what you want, and if you want me to do a tricky part, just say "your turn."

Okay, I'm finding "change x by"... it's in blue Motion... snapping it inside the if. Your turn — press the flag and see if it worked!

Ooh, a dragon? Someday List! We'll add it once the stars work.

Watch-outs
  • Parents taking over. The biggest risk of the night. Watch hands: if a parent has had the mouse for 3 minutes, whisper, "Can your director press the flag on this one?"
  • Parents comparing. Families move at wildly different speeds; a six-year-old family will be slower, and that's correct. Say it aloud once: "Fast doesn't mean better tonight. The game that's theirs wins."
  • Big ideas mid-build. Use the Someday List poster; a sticky note makes "not now" feel like "yes, later."
  • Scratch accounts for kids. Don't create child accounts tonight. Save to the parent's account or File → Save to your computer. Account and sharing decisions come in Lesson 5.2.
  • Keyboard focus. "The bowl won't move" is almost always "click the stage first."
  • Noise. Ten Pop sounds at once is a lot. Keep volumes low; it's fine to add sound last.
Check — quiz

Answers: huge idea → pick ONE main action, build the small version, Someday List the rest (B); the original Star hides because it's a hidden factory; only clones fall and get caught (A); hide and play sound until done first because deleting a clone cuts off its sound (B); the smallest playable version is bowl moves + stars fall + catching adds score (A).

4.4

Capstone Part 2 — Lives, Game Over & Launch Day

40 min · S5
Objectives
  • Reopen a saved project and restart momentum by playing first
  • Use a lives check inside the clone, then broadcast game over
  • Show a Game Over sprite, then stop all; tune the game until it feels right
  • Hold a launch day where the child explains the game and watches someone play
Teaching sequence
  1. Play first (2m). "Before we add anything, can you beat your score from before the break?"
  2. Step 8 — missing costs a life (≈ 10m). Inside the clone's forever, under the catch if: if ⟨(y position) < -170⟩ then → change lives by -1 → if ⟨(lives) = 0⟩ then broadcast game over → delete this clone. Make game over with New message. Demo script: "The star knows it was missed, so the star takes the life. And the delete goes last inside that if, or it keeps taking lives."
  3. Step 9 — GAME OVER (≈ 10m). Paint a new sprite, Text tool, "GAME OVER", name it Game Over. Scripts: when ⚑ clicked → hide; when I receive game over → go to front layer → show → stop all. "Show first, then freeze."
  4. Step 10 — music & tuning (≈ 8m, optional). Stage → Sounds → a Loops sound; when ⚑ clicked → forever → play sound (loop) until done. Tuning: -5 → -3 is easier; directors decide. Hand out the Project Completion checklist.
  5. Launch-day briefing (1m), then into the mini showcase on the run-sheet.
Lab — Star Catcher Finished + Launch Day

Steps 8–10 and the Project Completion checklist, then the rotating showcase: the Director explains the rules ("Use the arrows. Catch stars. Don't miss three!"), hands off, watches, and collects one "liked" and one idea. Reference: labs/module-4/l4-4-star-catcher-final.sb3 (your machine only; use it to show the finished game and to compare scripts when debugging).

Circulate for: the y position check outside the forever (stars still pile up); delete this clone outside the lives if (lives drop by 2–3); broadcast and receive using different messages; no green-flag hide on the Game Over sprite; ages 5–7: skip lives entirely, paint the sign and pick music instead.

Teach-It — finish strong (live, and the role-play card)

The new skill is handling frustration near the finish. Adults without a child: switch roles from 4.3 and use this card.

Kid card — Marcus, age 8

Tired after the break. You added step 8 and now every miss takes all three lives; the game ends instantly. You say "I hate this game, it's ruined," and push the mouse away. You calm down only if your coach makes the problem small. You'd rather save and stop than be lectured.

Before we add anything — can you beat your high score from last time? Show me!

It worked before we added this part, so the problem is only in this part. Let's read it together, one block at a time.

Let's save it and fix it with fresh eyes tomorrow. That's a real programmer move.

Watch-outs
  • Tears near the finish. Energy is lowest here. Stop on a win (step 8 working is a fine place to stop) and never mid-bug.
  • The last-minute fix from the parent. When it's broken at 1:44, parents grab the mouse "so they have something to show." Remind the room: the showcase works with whatever version last worked.
  • Lives never reach exactly 0 if reset game doesn't set lives to 3, or lives were made "For this sprite only" on the Bowl (the Star then can't see it).
  • Publishing pressure. Kids will ask to put it online. "Not tonight. Next session we learn how to share safely (Lesson 5.2)."
  • Showcase shyness. Some children won't speak to strangers. Let them point and press the flag while the parent reads the design card aloud.
Check — quiz

Answers: lives drop by 2–3 because delete this clone isn't inside the lives if (B); the Game Over sprite shows first so the sign is on screen when everything freezes (A); game breaks near the finish → shrink it to the last change, or save and stop (B); GAME OVER still visible at the start of a new game → add when ⚑ clicked → hide to the Game Over sprite (C).

Closing the Module

Module 4 wrap-up

Across two sessions the grown-ups learned clones and custom blocks, then used them with their child from a paper plan to launch day. Recap: stamp and prints → recipe cards → design card → smallest playable version → one feature at a time → launch. Preview S6: "Tonight you probably noticed how hard it is to keep your hands off the mouse. Next session is all about that: teaching Scratch to your child."

Before S6, note which parents struggled most with taking over; their reflections make great openers for Lesson 5.1.
