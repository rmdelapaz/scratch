4.1

Clones — One Sprite, Many Copies

40 min · S4
By the end you can
  • Explain a clone using the rubber-stamp idea
  • Use create clone of myself, when I start as a clone, and delete this clone
  • Build a hidden "stamp" that keeps making clones, and clean them up
Key ideas
  • A clone is a copy of a sprite made while the program runs. The original is the stamp; clones are the prints.
  • All three clone blocks are at the very bottom of Control.
  • A clone copies everything, including being hidden. Start every clone script with show.
  • when ⚑ clicked runs only on the original. when I start as a clone runs only on each new clone.
  • Scratch allows about 300 clones. Every clone needs a way to reach delete this clone.
Worked example — the stamp and the prints
when ⚑ clicked
hide
forever
go to x: pick random -220 to 220 y: 180
create clone of myself
wait 1 seconds
when I start as a clone
show
repeat until ⟨ y position ⟩ < -170
change y by -5
delete this clone

Left: the stamp (the original, hidden). Right: what every print does. Both scripts go on the same Star sprite.

Your turn — Falling Stars
  1. New project. Hover the cat-face button (bottom right) → Choose a Sprite → Star. Pick a dark backdrop (Stars or Night City).
  2. Build the stamp script. Click the green flag: nothing appears, and that's correct.
  3. Build the clone script. The < block is in green Operators; drop blue y position (bottom of Motion) in its left slot and type -170.
  4. Click the flag: stars rain down. Press stop: they all vanish. Save it.
  5. Make it yours: wait 0.3 for a meteor shower; turn ↻ 5 degrees inside the repeat; set size to (pick random 30 to 100) % before show.
Teach-It practice — Stamps and prints

Make it physical first (a rubber stamp, or a cookie cutter and play-dough). When the stamp script shows nothing, don't fix it. Ask:

Where's the stamp now? In my hand, not on the paper. What should each print do after it lands?

We hid the stamp. The prints are copies of the stamp… so what do the prints look like right now?

Who should do the stamping — the stamp or the prints?

After the role-play: which question helped your "child" find the bug? What did you want to do instead?

4.2

My Blocks — Make Your Own Blocks

35 min · S4
By the end you can
  • Make a custom block with My Blocks → Make a Block
  • Put its steps under the pink define hat and use it from any script in that sprite
  • Add an input so one block can behave differently each time
Key ideas
  • A custom block is a recipe card: write the steps once, give them a name, then use the name. Programmers call it a function.
  • Whatever is snapped under define is what the block does. Using the block is called calling it.
  • An input is a slot you fill each time (e.g. how many times to dance). To use it, drag the pink oval out of the define hat; don't type the word.
  • Leave Run without screen refresh unticked, or animations happen instantly.
  • My Blocks belong to one sprite. Drag the define script onto another sprite to copy it.
Worked example — define once, call anywhere
define jump
repeat 10
change y by 10
repeat 10
change y by -10
when space key pressed
jump
define dance times times
repeat times
turn ↻ 15 degrees
wait 0.2 seconds
turn ↺ 15 degrees
wait 0.2 seconds
Your turn — Three custom blocks
  1. New project with the cat. My Blocks → Make a Block → type jump → OK. Build the define script above. Call it from when space key pressed and when this sprite clicked.
  2. Make dance: Add an input (number or text) named times, then Add a label "times." Drag the times oval into the repeat. Call dance 3 times, say Ta-da! for 1 seconds, dance 6 times under the green flag.
  3. Make variables score and lives (For all sprites). Then build reset game:
define reset game
set score to 0
set lives to 3
go to x: 0 y: -150
show
when ⚑ clicked
reset game

You'll use reset game again at Family Build Night. Challenge: jump (height), using (height / 10) going up.

Teach-It practice — New words for the computer

Start away from the screen with a "new word" game, then let your child find the repeated blocks and name the block themselves (silly names stick).

I'm going to teach you a new word: zoomba. Zoomba means clap twice and spin around. Ready? Zoomba! Now let's teach the computer a new word.

I see those same blocks twice. What would you call what they do? What if that were one block with that name?

The value lives in this pink oval. Drag it out and see what happens.

After the role-play: how did you respond to "copying is faster, why bother?"

4.3

Capstone Part 1 — Plan It & Build the Core

S5 · Family Build Night
By the end you can
  • Plan a game on paper with a Game Design Card and a Someday List
  • Build the smallest playable version of Star Catcher first
  • Share the work: your child directs, you type only when asked
Key ideas
  • Plan before you code: brainstorm → pick ONE small idea → sketch it → list the pieces → build the smallest playable version → add one thing at a time.
  • Big ideas that arrive mid-build go on the Someday List. "Not now" becomes "yes, later."
  • The original Star is a hidden factory: it makes clones; only clones fall and get caught.
  • Test after every step. If it worked a minute ago, the bug is in the last thing you added.
  • A clone that is deleted stops its sound, so a caught star hides, plays its sound until done, then deletes itself.
Worked example — the three core scripts
when ⚑ clicked
reset game
forever
if key right arrow pressed? then
change x by 10
if key left arrow pressed? then
change x by -10
when ⚑ clicked
hide
wait 1 seconds
forever
create clone of myself
wait pick random 0.5 to 1.5 seconds
when I start as a clone
go to x: pick random -220 to 220 y: 170
show
forever
change y by -5
if touching Bowl? then
change score by 1
hide
play sound Pop until done
delete this clone
Your turn — Star Catcher Part 1 (press the flag after every step)
  1. Set the stage. New project; right-click the cat → delete. Add Bowl and Star; pick the Stars backdrop.
  2. Variables. Make score and lives, For all sprites, both ticked to show on stage.
  3. reset game on the Bowl. Same block as Lesson 4.2 (set score 0, lives 3, go to x: 0 y: -150, show).
  4. Move the Bowl. The left script above. Click the stage, then tap the arrows.
  5. Star factory. The middle script, on the Star.
  6. Each clone falls. The right script without the if. Stars pile up at the bottom for now; that's expected.
  7. Catch the stars. Add the Pop sound (Sounds tab), then the if touching Bowl? part.
✅ Checkpoint — smallest playable version

Stars fall, you catch them, the score climbs. That's a real game. Type Star Catcher in the title box and save (File → Save now, or File → Save to your computer). Behind? That's normal with a child driving; your facilitator has a rescue file so you can carry on together.

Teach-It practice — Build it as a team

Director (your child): decides what the game is, how it looks, and whether a change is right; presses every green flag. Typist (you): takes the mouse for fiddly bits, only when asked, narrates, and hands it straight back.

You're the boss of this game. I'm your helper. Tell me what you want, and if you want me to do a tricky part, just say "your turn."

Okay, I'm finding "change x by"... it's in blue Motion... snapping it inside the if. Your turn — press the flag and see if it worked!

Ooh, rocks too? Someday List! We'll add it once the stars work.

After Family Build Night: when was it hardest not to grab the mouse? What did you do instead?

Capstone Part 2 — Lives, Game Over & Launch Day

S5 · Family Build Night
By the end you can
  • Pick up a saved project by playing it first
  • Use a lives check inside the clone and broadcast game over
  • Show a GAME OVER sign, then stop all; tune the game until it feels right
  • Hold a launch day where your child explains the game and watches someone play
Key ideas
  • The star knows it was missed, so the star takes the life. delete this clone goes last inside that if, so each miss costs exactly one life.
  • A broadcast lets one sprite tell another "it's over." The Game Over sprite shows first, then runs stop all, which freezes everything and removes all clones.
  • Tuning numbers (fall speed, wait between stars) turns a working game into a fun one.
  • Start by playing; stop on a win, never mid-bug.
Worked example — misses cost lives, then GAME OVER
when I start as a clone
go to x: pick random -220 to 220 y: 170
show
forever
change y by -5
if touching Bowl? then
change score by 1
hide
play sound Pop until done
delete this clone
if y position < -170 then
change lives by -1
if lives = 0 then
broadcast game over
delete this clone
when ⚑ clicked
hide

when I receive game over
go to front layer
show
stop all
Your turn — Finish Star Catcher (steps 8–10)
  1. Play one round first. Beat your score from before the break.
  2. Step 8 — a miss costs a life. Add the second if inside the clone's forever, under the catch if. For game over, open the broadcast dropdown → New message.
  3. Step 9 — GAME OVER. Paint a new sprite, write GAME OVER with the Text tool, name it Game Over, add its two scripts.
  4. Step 10 — music & tuning. Stage → Sounds → a Loops sound; when ⚑ clicked → forever → play sound (loop) until done. Too hard? -5 → -3. Too easy? The opposite.
✅ Project Completion

☐ Bowl moves left and right · ☐ Green flag resets score to 0 and lives to 3 · ☐ Original star hidden; clones fall from random spots · ☐ Catching adds 1 and plays a sound · ☐ A miss removes 1 life and the star disappears · ☐ At 0 lives GAME OVER appears and everything stops · ☐ Green flag starts a fresh game · ☐ Project saved
