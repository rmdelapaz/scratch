4.1 · Clones — One Sprite, Many Copies

Q1
The original star is hidden. You make clones, but none appear. Why?
B) Clones start hidden, just like the original, and need a "show" block
Why: a clone copies everything about the original, including being hidden. Add show right under when I start as a clone.
Q2
Which script runs only on the new clones, never on the original?
C) when I start as a clone
Why: when ⚑ clicked runs only on the original (clones are made after the click); when I receive runs on the original and every clone.
Q3
The game slows, then new stars stop appearing. Most likely cause?
A) Clones are never deleted, so they pile up toward the 300 limit
Why: off-screen clones still count. Past about 300, create clone silently does nothing. Every clone must reach delete this clone.
Q4
create clone of myself inside the when I start as a clone script — what happens?
B) Every clone makes another clone, flooding the screen until Scratch's limit
Why: each new clone runs the clone script, so each one stamps again: a chain reaction. Coach with "Who should do the stamping — the stamp or the prints?"
Lab solution — Falling Stars · labs/module-4/l4-1-falling-stars.sb3

Common wrong answers & how to coach them
  • Nothing ever appears → no show in the clone script. Ask: "The stamp is hidden. What do its prints look like?"
  • One clump of stars → no go to before stamping, or no wait. Ask: "Where is the stamp when it presses down? Does it ever move?"
  • Stars vanish instantly → repeat until touching edge?. Each star is born touching the top edge. Ask: "Where does a new star start?"
  • The original falls → the falling loop is under when ⚑ clicked. Ask: "Is this running on the stamp, the prints, or both?"
  • y position in the wrong slot (right side of <) → the test reads "-170 < y" and is true at once. Read the block aloud together, left to right.

4.2 · My Blocks — Make Your Own Blocks

Q1
Where do you put the steps your new block should do?
B) Under the pink "define" block
Why: the define hat is the recipe card. The green-flag script only calls the block; the dialog only sets name and inputs.
Q2
The jump works but the cat teleports instead of hopping. Likely cause?
A) "Run without screen refresh" is ticked
Why: with refresh off, Scratch skips drawing the in-between frames. Right-click the define hat → Edit → untick.
Q3
reset game was made on the Bowl but is missing on the Star. Why?
C) Custom blocks belong to the sprite they were made in
Why: My Blocks are per sprite. Drag the define script onto the other sprite's thumbnail in the sprite list to copy it.
Q4
How do you make the repeat use the number passed to dance (times)?
B) Drag the pink times oval out of the define hat into the repeat slot
Why: dragging the oval gives you a copy that holds the passed-in value. Typing "times" is just text; a new variable is a different thing and won't receive the number.

Common wrong answers & how to coach them
  • "My block does nothing" → steps sitting near, but not snapped under, the define hat. Drag the hat: whatever moves with it is attached.
  • Dance never repeats / repeats 0 times → the word typed into the slot. Point at the pink oval: "The value lives in here — drag it out."
  • "My block disappeared" → a different sprite is selected. Click the sprite it was made in.
  • reset game shows a red error / empty dropdown → variables not made yet. Make score and lives first.

4.3 · Capstone Part 1 — Plan It & Build the Core

Q1
A huge idea with dragons, shops, and ten levels. Best first move?
B) Pick the ONE main action, build that small version first, and save the rest for a "someday list"
Why: games started by dragging blocks grow too big to finish. Shrink where you start without crushing the idea.
Q2
Why does the original Star hide and only make clones?
A) It's a hidden "factory." Only the clones fall and get caught
Why: hidden sprites can still make clones; that's the whole job of the original. Hiding doesn't affect speed.
Q3
Why hide and play sound Pop until done before delete this clone?
B) Deleting a clone cuts off its sound, so it hides and finishes the pop first
Why: hide makes the star vanish instantly (it feels caught); until done lets the pop finish before the clone goes.
Q4
Which is the "smallest playable version" of Star Catcher?
A) Bowl moves + stars fall + catching adds score
Why: it's the least you can build that is still a game someone can play. Lives and GAME OVER are additions (Part 2); the card alone isn't playable.

Common wrong turns & how to coach them (coach the parent; let the child fix)
  • Bowl won't move → stage lacks keyboard focus, or the ifs sit outside the forever. "Click the stage once." Then trace the forever's mouth with a finger.
  • A frozen star at the top → the original isn't hidden. "Which star is the factory? Should we see it?"
  • Score doesn't reset on replay → reset game not called, or placed inside the forever (score stuck at 0).
  • Pop is cut off → start sound used, or delete this clone before the sound.
  • lives made "For this sprite only" → looks fine now but breaks step 8. Check it at the checkpoint: a sprite-only variable's stage readout shows the sprite name first (Bowl: lives). Easiest fix: delete it and remake it For all sprites.
  • Design card (not graded): look for one main action, a clear way to score and to lose, and a Someday List with at least one item. If a card lists five main actions, help the family circle one.

4.4 · Capstone Part 2 — Lives, Game Over & Launch Day

Q1
Each missed star takes 2 or 3 lives instead of 1. Likely cause?
B) delete this clone isn't inside the lives if, so the star keeps subtracting
Why: the star stays below -170 and loses a life on every trip around the forever until it's deleted. Delete must be the last block inside that if.
Q2
Why does the Game Over sprite show itself before stop all?
A) So the sign is already on screen when everything freezes
Why: nothing runs after stop all. It also removes every clone, which is what we want.
Q3
The game breaks near the finish; your child is close to tears. Best move?
B) Point out it worked before the last change, look at just that part together, or save and stop for today
Why: shrinking the bug to the last change makes it solvable, and stopping to come back fresh is a real programmer move. Taking the mouse takes the win away.
Q4
GAME OVER is still on screen when a new game starts. The fix?
C) Give the Game Over sprite a "when ⚑ clicked → hide" script
Why: the sign stays shown after stop all until something hides it. Moving stop all first would stop the show; lives at 0 would end every game instantly.

Common wrong turns & how to coach them
  • Stars still pile up → the y position check is outside the forever (it runs once, at birth). "Does the star ask this question once or all the way down?"
  • Lives drop by more than 1 → delete this clone outside the lives if (Q1).
  • GAME OVER never shows → broadcast and receive use different messages, or lives never hit exactly 0 (not reset to 3, or a "For this sprite only" lives on the Bowl that the Star can't see).
  • Music stutters or overlaps → start sound in the forever. Use play sound … until done.
  • Ages 5–7 skipped lives → that is a complete, correct outcome. Credit the painted sign, the music, and the launch.
  • Launch day: "correct" means the child explained the rules, kept hands off while someone else played, and collected one idea for the Someday List.
