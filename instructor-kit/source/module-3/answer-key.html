3.1 · An Interactive Animated Story

Q1
Two sprites need to take turns talking. What coordinates them?
A) broadcast and "when I receive"
Why: the next line starts only when the cue is actually sent. Matched wait times drift and break.
Q2
Which block moves a sprite smoothly over time?
B) glide _ secs to x/y
Why: go to x/y teleports instantly. glide slides over the number of seconds you give it.
Q3
Both characters talk at the exact same time. Likely cause?
A) Both start with "when ⚑ clicked" instead of "when I receive"
Why: every green-flag script starts at the same moment. Only line 1 should use the flag.
Q4
Where does the backdrop-changing script go?
B) On the Stage: "when I receive night" then "switch backdrop to"
Why: the Stage owns the backdrops and can listen for broadcasts just like a sprite. Click the Stage (right of the sprite list) before adding its blocks.
Lab solution — A Conversation That Plays Itself

Reference: labs/module-3/l3-1-conversation.sb3. A Forest backdrop, a Cat and a Bear, and a chain of four cues: Cat on the flag → line 2 → Bear → line 3 → Cat → line 4 → both glide off. Words, characters, and coordinates will vary. Check the structure.

when ⚑ clicked
go to x: -200 y: -100
glide 2 secs to x: -60 y: -100
say Hi Bear! for 2 seconds
broadcast line 2
when I receive line 2
say Hello Cat! for 2 seconds
broadcast line 3
when I receive line 3
say Want to explore? for 2 seconds
broadcast line 4
when I receive line 4
say Let's go! for 1 seconds
glide 2 secs to x: 240 y: -100

(The last script goes on both sprites, so they leave together. The Bear's version usually skips the say.)

Common wrong answers and how to coach them: both sprites talking at once → "Which of your scripts start with the flag? Only line 1 should." · a line that never plays → the when I receive dropdown names a different message ("line2" vs "line 2"). Open the dropdown and compare. · the line-4 glide only moves one sprite → the receiving script was added to one sprite only. · the Bear has no Bear scripts → they were built while the Cat was selected. Drag the script onto the Bear in the sprite list to copy it.

3.2 · A Simple Game with Variables & Score

Q1
What is a variable?
A) A named box that stores a value the program can change
Why: it has a name (score) and a value (0, then 1, then 2…), like a whiteboard labeled SCORE.
Q2
To add one point to the score, you use…
B) change score by 1
Why: change adds to what's already there. set score to 1 would reset it to 1 every time.
Q3
Where should "set score to 0" go?
A) Right after the green flag, before the game loop
Why: it should run once per game. Inside the forever it would wipe the score on every drop.
Q4
You can't see the score on the stage. What do you do?
C) Tick the checkbox next to the variable in the Variables palette
Why: the checkbox toggles the live readout on the stage. (The show variable block does the same thing from code.)
Lab solution — Catch the Apple

Reference: labs/module-3/l3-2-catch-the-apple.sb3. Two sprites (Cat, Apple) and one variable, score, set "For all sprites" with its stage readout showing. This file is also the solution to the Bug Hunt.

when ⚑ clicked
set score to 0
forever
go to x: pick random -200 to 200 y: 170
repeat until touching Cat?
change y by -8
if y position < -170 then
go to x: pick random -200 to 200 y: 170
change score by 1
when ⚑ clicked
forever
go to x: mouse x y: -140

Common wrong answers and how to coach them: score jumps by several per catch → the apple lingers on the cat. Make sure the loop goes back to the top go to right after scoring. · score never rises → the touching dropdown says "mouse-pointer," or the Cat's y keeps it below the apple's path. · apple frozen at the top → they used if touching edge? for the bottom check. The apple starts touching the top edge, so it resets every frame. Use y position < -170. · "mouse x" typed as text → it must be the round Sensing reporter dropped into the slot. · Timer challenge: a second green-flag script, set [time left] to 30 → repeat until <(time left) = 0> → wait 1 seconds, change [time left] by -1 → then broadcast [game over], stop all.

3.3 · Debugging & Remixing

Q1
The golden rule of debugging is…
A) Change one thing at a time, then test
Why: change five things and you'll never know which one mattered, or which one broke something new.
Q2
What does "See Inside" do on a shared project?
A) Opens the project's code to explore how it was made
Why: it turns the whole Scratch community into a free textbook. Remix (signed in) is the separate step that makes your own copy.
Q3
Your child is melting down over a stubborn bug. Best move?
B) Have them explain it aloud, or take a short break
Why: the rubber duck often surfaces the bug mid-sentence, and a break is a real debugging strategy. Grabbing the mouse ends the learning.
Q4
Green flag clicked and nothing happens. Most likely suspect?
B) The code is on a different sprite than you think
Why: it's the first row of the usual-suspects table. Click each sprite in the sprite list and look for the script.
Lab solution — The Bug Hunt

Starter: labs/module-3/l3-3-bug-hunt-starter.sb3 is the 3.2 game with four planted bugs. Solution: labs/module-3/l3-2-catch-the-apple.sb3 (scripts drawn above). Each bug below shows the symptom a pair should watch, the cause, and the fix with the corrected script. The symptoms overlap (with bug 4 in place, the score races even while bug 3 keeps the apple stuck at the top), so accept any order, as long as each fix was one change followed by a test.

Bug 1 · Cat script
Symptom: the cat ignores left–right mouse movement and slides sideways when the mouse moves up and down. It "drifts strangely."
Planted (wrong)
when ⚑ clicked
forever
go to x: mouse y y: -140
Fixed
when ⚑ clicked
forever
go to x: mouse x y: -140
Fix: replace the mouse y reporter with mouse x (Sensing). The x slot needs the mouse's left–right number. Coach: "Move the mouse only sideways. Does the cat? Which number does the x slot get?"
Bug 2 · Apple script, top
Symptom: the score doesn't reset. Press the green flag again and it carries on from the last game's number. (The first game may even open with a leftover score.)
Planted (wrong)
when ⚑ clicked
forever
go to x: pick random -200 to 200 y: 170
…
Fixed
when ⚑ clicked
set score to 0
forever
go to x: pick random -200 to 200 y: 170
…
Fix: add set [score] to 0 between the hat block and forever. Common wrong fix: putting it inside the forever, which zeroes the score on every drop so it never climbs past 1. That's a good teachable second bug. Coach: "What wipes the whiteboard at the start of a game?"
Bug 3 · Apple script, falling loop
Symptom: the apple never falls. It sits at the top of the stage, so nothing can ever be caught. (While bug 4 is still in place, the score races up even though the apple isn't moving. That clue points at the loop.)
Planted (wrong)
repeat until touching Cat?
change y by 8
…
Fixed
repeat until touching Cat?
change y by -8
…
Fix: change the change y by value from 8 to -8. Bigger y means up, so the apple keeps pushing into the top of the stage (Scratch holds it on-screen) instead of falling. Helper to suggest: tick the Apple's y position checkbox (bottom of Motion) and watch. The number never goes down. Coach: "Which way does y go when it gets bigger? Which block moves the apple up or down?"
Bug 4 · Apple script, nesting
Symptom: the score races upward while the apple is still falling, one point per step, whether or not it's caught.
Planted (wrong)
repeat until touching Cat?
change y by -8
if y position < -170 then
go to x: pick random -200 to 200 y: 170
change score by 1
Fixed
repeat until touching Cat?
change y by -8
if y position < -170 then
go to x: pick random -200 to 200 y: 170
change score by 1
Fix: drag change [score] by 1 out of the repeat-until's mouth and drop it directly below the repeat-until (still inside forever). It should run once, after the catch. Common wrong fix: dropping it loose on the canvas or trying to attach it under forever (which has no bottom notch). A block that isn't connected never runs. Have them drag the script and check that the +1 moves with it. Coach: "How many times does the +1 run while one apple falls? Which loop is it inside?"
Coaching the Bug Hunt as a whole

Pairs that fix everything by rebuilding from scratch: accept it, then ask them to name the one block that was different. Pairs that fix bug 3 and think the score is still broken: it is. That's bug 4. Praise the one-change discipline that let them tell the two apart. Pairs who rewrite the bottom check as if touching edge?: the apple freezes at the top again, because at y: 170 it already touches the top edge. That's a bonus teachable moment, and it's why the reference uses y position < -170. Fully fixed check: the cat follows the mouse sideways, the apple falls, a miss scores nothing and restarts at the top, a catch scores exactly 1, and a second green flag starts again at 0.
