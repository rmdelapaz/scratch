1.1

What Is Scratch & Why Kids Love It

25 min
By the end you can
  • Explain in one sentence what Scratch is
  • Say how block coding differs from typed code
  • Introduce Scratch to your child with confidence
Key ideas
  • Scratch is a free website where kids make games, animations and stories by snapping colorful blocks together instead of typing code. It's made by MIT and run by the non-profit Scratch Foundation.
  • Three words: sprite (a character or object, like the cat), stage (the screen where the action happens), blocks (the instructions you snap together).
  • Blocks only snap together if they make sense, so there are no typos to break things.
  • Color = category: blue Motion, purple Looks, pink Sound, gold Events, orange Control, light-blue Sensing, green Operators, dark-orange Variables.
  • You are a coding buddy, not an expert. Add the word "yet": "I don't get it yet."
Worked example — same program, two ways
# typed code (Python-style)
when program starts:
    move(10)
    say("Hello!", 2)

Miss a colon or misspell say and it breaks.

when ⚑ clicked
move 10 steps
say Hello! for 2 seconds

Snaps together like LEGO. Nothing to misspell.

Your turn — Click around
  1. Open scratch.mit.edu and click Create. The cat is waiting.
  2. Drag any block into the middle and click it. What happened?
  3. Drag one block onto another until it snaps. Try to snap a gold "when…" block under something. Notice that it won't go.

A Guided Tour of the Scratch Editor

33 min
By the end you can
  • Name the four areas of the editor and what each does
  • Find any block with the colored category menu
  • Run and stop a project, and save your work
Key ideas
#ZoneWhereWhat it's for
1Blocks PaletteLeftThe menu of instructions, sorted by color/category
2Code AreaMiddleWhere you drag and snap blocks together
3StageUpper rightThe "screen" where sprites act out your code
4Sprite ListLower rightAll your characters; click one to code it
  • Green flag runs every when ⚑ clicked script. Red stop halts everything.
  • Code belongs to the selected sprite. If "nothing works", first check which sprite is highlighted.
  • Tabs at the top-left: Code (blocks), Costumes (a sprite's outfits, which is how animation works), Sounds.
  • Saving: signed in → File → Save now. Not signed in → File → Save to your computer, and reopen it later with File → Load from your computer.
  • Kid accounts: use Join Scratch, a username that hides their real name, and your email as parent/guardian. Then click the confirmation link in that email.
Worked example — the block you'll use most

Gold Events holds the starter block. Almost every program begins with it:

when ⚑ clicked
move 10 steps
say Hello!
start sound Meow
wait 1 seconds

Right: one block each from Motion, Looks, Sound and Control. You can recognize them by color before you read the words.

Your First Project: Make the Cat Move & Talk

27 min
By the end you can
  • Drag, drop and snap blocks into a script
  • Start a program with when ⚑ clicked
  • Test, tweak and fix a simple project
  • Coach your child with questions, not instructions
Key ideas
  • A program starts with an Event ("hat") block, like when ⚑ clicked.
  • Blocks snap into a stack. Watch for the grey shadow before you let go.
  • Scratch runs a stack top to bottom, in order. That's a sequence. Change the order and you change the behavior.
  • Click a white oval to change words or numbers.
  • Bugs are normal: "It doesn't work… yet."
Worked example — build it one block at a time
when ⚑ clicked
when ⚑ clicked
move 10 steps
when ⚑ clicked
move 50 steps
say Hello! I'm Scratch Cat for 2 seconds
Your turn — Make the Cat Move & Talk
  1. New project (File → New). Check that the cat (Sprite1) is selected in the sprite list.
  2. Events (gold): drag when ⚑ clicked into the code area.
  3. Motion (blue): snap move 10 steps underneath. Click the green flag.
  4. Looks (purple): snap say Hello! for 2 seconds under the move block.
  5. Change the message to your own words and 10 to 50. Run it!
  6. Cat stuck at the edge? Add go to x: 0 y: 0 right under the hat.
  7. Make it yours (pick any): a joke message · 200 steps · a second say · start sound Meow · change size by 25 · turn ↻ 15 degrees · next costume between move and say.
  8. Save it (File → Save now, or Save to your computer).

What happened when I swapped move and say?

If it doesn't work
  • Nothing happens on the green flag → the blocks aren't snapped (drag the hat and see whether everything comes with it), or the wrong sprite is selected.
  • Cat moves but doesn't talk → the say block isn't attached. Drag it until it snaps under move.
  • Cat walks off-screen → each run adds 50 more steps. Drag the cat back, or add go to x: 0 y: 0.
  • Cat is upside-down after turning → set its rotation to "left-right" in the sprite info.
Teach-It practice — "Treasure hunt, not dictation"

Coach your partner through the build using questions only. The words, the number and the green flag belong to the child.

"We want the cat to walk. Which color do you think has the moving blocks?"
"The message is yours. What should the cat say?"
"Hmm, it didn't work yet. Interesting! Why do you think it did that?"

Role-play reflection: when my "child" got stuck, what did I say? What would I say differently next time?

Self-check

A) move 10 steps
B) when ⚑ clicked

Q2

A) Restart the computer
B) Is the "say" block snapped onto the stack?
C) Buy the full version
Q4

A) Nothing. Scratch picks its own order

Ideas to try: one thing you'd like the cat to do that you don't know how to do yet.

2.1

Sequences & Timing

33 min
By the end you can
  • Explain what a sequence is and why order matters
  • Use the wait block to control timing and pacing
  • Build a short multi-step routine that runs like a little performance
Warm-up — Program the Facilitator

Write the class's final instructions that got the "robot" out the door. Circle any step that got repeated over and over.

Key ideas
  • A sequence is a list of steps run one after another, top to bottom. Think of a recipe.
  • Computers are literal. Same blocks in a different order = different behavior. A surprise usually means the recipe isn't what you intended yet.
  • wait (1) seconds (orange Control) adds pacing. Decimals like 0.5 work.
  • say … for 2 seconds already pauses before the next block. Plain say … moves straight on.
Worked example — order changes everything
when ⚑ clicked
move 100 steps
say Made it! for 2 seconds
when ⚑ clicked
say Here I go! for 2 seconds
move 100 steps

Left: walks, then speaks. Right: speaks, then walks. The blocks are the same and only the order is different.

Your turn — Build a Greeting Routine
  1. Start with when green flag clicked (Events).
  2. Add go to x: 0 y: 0 (Motion) so the cat always starts centered.
  3. Add say "Hi, I'm Scratchy!" for 2 seconds (Looks), then wait 1 seconds (Control).
  4. Add move 120 steps, then say "Welcome to my world!" for 2 seconds.
  5. Challenge: between the wait and the move, add start sound Meow and next costume.
when ⚑ clicked
go to x: 0 y: 0
say Hi, I'm Scratchy! for 2 seconds
wait 1 seconds
move 120 steps
say Welcome to my world! for 2 seconds

2.2

Loops — Making Things Repeat

27 min
By the end you can
  • Use the repeat and forever loops
  • Tell what goes inside a loop vs outside it
  • Build a smooth walking animation, and stop a runaway forever loop
Key ideas
  • A loop says "do this again and again." One loop replaces a pile of copied blocks.
  • repeat (10) = a set number of times, then move on. forever = until you press the red stop sign.
  • Loops are C-shaped. Only the blocks inside the mouth repeat.
  • Anything placed after a forever loop never runs. That's the loop doing its job.
Worked example — inside vs outside
repeat 3
say Ha! for 1 seconds
repeat 3
move 10 steps
say Done! for 1 seconds

Left: "Ha!" three times. Right: moves three times, then says "Done!" once.

Your turn — A Real Walking Cat
  1. when green flag clicked, then go to x: -200 y: 0 (start at the left).
  2. Add a repeat 20 loop (Control).
  3. Inside the loop: move 20 steps, next costume, wait 0.1 seconds.
  4. Press the green flag. Try a wait of 0.3, then 0.05. What changes?
  5. Challenge: wrap the walk in forever, add if on edge, bounce and set rotation style [left-right].
when ⚑ clicked
go to x: -200 y: 0
repeat 20
move 20 steps
next costume
wait 0.1 seconds

Conditionals & Sensing — Making Choices

30 min
By the end you can
  • Use if/then and if/then/else to make decisions
  • Read Sensing blocks (touching, key pressed, mouse down)
  • Combine forever + if to check things constantly, and drive the cat with the arrow keys
Warm-up — "If it's raining, then…"

Write two rules from your own household: one if/then, and one if/then/otherwise.

Key ideas
  • if <> then (Control) runs the blocks inside only when the condition is true. Otherwise Scratch skips them.
  • The pointy hexagon slot takes a true/false question. Most come from light-blue Sensing.
  • forever + if is the "game loop": it keeps asking, so the sprite reacts the instant something becomes true. Without forever, the check happens once.
  • if/then/else has two mouths. Read "else" as "otherwise."
Worked example — the game loop and two paths
when ⚑ clicked
forever
if touching mouse-pointer? then
start sound Meow
if key space pressed? then
say Jump! for 1 seconds
else
say Waiting… for 1 seconds

Read them aloud: "Forever: if touching the pointer, meow." "If space is pressed, say Jump. Otherwise, say Waiting."

Your turn — Drive the Cat with Arrow Keys
  1. when green flag clicked, then a forever loop.
  2. Inside the forever, add if <key right arrow pressed?> then with change x by 10 inside. Test it.
  3. Right-click the if → Duplicate three times. Change each to left (x −10), up (y 10), down (y −10).
  4. Press the green flag, click the stage once, and drive.
  5. Challenge: add if <touching edge?> then say "Ouch!".
when ⚑ clicked
forever
if key right arrow pressed? then
change x by 10
if key left arrow pressed? then
change x by -10
if key up arrow pressed? then
change y by 10
if key down arrow pressed? then
change y by -10

3.1

An Interactive Animated Story

28 min
By the end you can
  • Add sprites and a backdrop from the libraries
  • Place sprites with go to and move them smoothly with glide
  • Make characters take turns with broadcast and when I receive
Key ideas
  • The stage is a grid: x is left–right (−240 to 240), y is down–up (−180 to 180), and the centre is 0, 0. Drag a sprite and read its x/y under the stage.
  • go to x: y: teleports (good for a starting spot). glide _ secs to x: y: slides (good for entrances).
  • Sprites can't see each other's scripts. A broadcast is an invisible signal that any sprite can send and any sprite can listen for, like a stage director calling a cue.
  • Only the first line starts with when ⚑ clicked. Every later line starts with when I receive.
Worked example
when ⚑ clicked
go to x: -200 y: -100
glide 2 secs to x: 0 y: -100
say Hi Bear! for 2 seconds
broadcast your turn
when I receive your turn
say Hi Cat! Nice day! for 2 seconds

Left: the Cat's script (sends the cue). Right: the Bear's script (listens for it). Both gold blocks are in Events. Choose New message the first time and give the cue a clear name.

  3. Other character (when I receive [line 2]): reply, then broadcast [line 3].
  4. Cat (when I receive [line 3]): reply, then broadcast [line 4].
  5. Both (when I receive [line 4]): say goodbye and glide off together.
  6. Bonus: click the Stage and give it when I receive [night] → switch backdrop to a night scene. Have a character broadcast "night."

  • Recognize the most common Scratch bugs

Key ideas
  • A bug just means "not doing what I expected yet." The computer does exactly what the blocks say. Debugging is finding the gap between what you said and what you meant.

5.1

The Art of Not Taking Over

20 min
By the end you can
  • Give the least help that unblocks your child, then fade it
  • Ask a guiding question instead of giving the answer
  • Praise effort and strategy, and teach the word "yet"
Key ideas
  • The struggle is the lesson. Fixing it for them quietly says "this is too hard for you."
  • Scaffolding is help that fades: I lead → they lead, I prompt → they do it, I watch → they teach me or a sibling.
  • Question toolkit: What do you want to happen? What happened instead? Which block is in charge of that? What could we try to test it? Where have we seen this before?
  • Praise the process ("You tested one block at a time"), not the talent ("You're a genius"). Add "…yet" to every "I can't."
  • Productive struggle: bored → raise the bar; frustrated → shrink the step; boiling over → take a break (a real strategy, not a failure).
Worked example — coaching a real bug

Your child's Star Catcher stars fall, but the score never goes up. Here's the star clone's script:

when I start as a clone
go to x: pick random -220 to 220 y: 170
show
if touching Bowl? then
change score by 1
delete this clone
forever
change y by -5

You see it instantly: the if touching Bowl? check runs once, at the top of the screen, before the star falls. It belongs inside the forever. Don't say that. Climb the help ladder one rung at a time and stop as soon as your child is moving again:

  1. "What do you want to happen when a star hits the bowl?"
  2. "Which script is in charge of the score?"
  3. "Let's read the star's script out loud. When does it check for the bowl?"
  4. "What would happen if the check were inside the loop?"
  5. Last resort: point to the if block and the forever block. They still do the dragging.
Your turn — Hands-off coaching rounds
  1. Pair up. The "child" draws a kid card and holds the mouse. The coach may not touch the mouse or trackpad.
  2. Open the buggy project your facilitator provides. Coach for 4 minutes using only questions and process praise.
  3. Swap roles, draw a new card, repeat.
Teach-It practice

How about I'm your hands and you're the boss? I'll only drag the blocks you point to.

You can't make the stars fall… yet. Let's just get one to move first.

5.2

Sharing Safely & the Scratch Community

18 min
By the end you can
  • Set up a Scratch account the safe way (or decide not to need one yet)
  • Explain "private until shared" and the community's protections
  • Write family sharing rules and have the "before sharing" talk
Key ideas
  • Scratch is run by a non-profit, collects minimal data, and asks for a parent/guardian email.
  • Projects are private until your child clicks Share. Sharing is a choice, and an account is optional (File → Save to your computer works without one).
  • The community is moderated, has short kid-readable Community Guidelines, and has no private messaging.
  • Comment controls: Report, turn comments off, delete comments, report and block unwanted users.
  • It's still the internet: shared device or common room, regular check-ins, and "show me any mean comment."
Worked example — one family's sharing rules
The Rivera family Scratch rules

1. Our username never has a real name, school, or birth year. (StarChef_77 ✓ · LeoMartinez2014 ✗)

2. No real name, address, school, phone number, or photos of us in projects or comments.

3. Scratch lives on the family laptop in the kitchen.

4. If anyone is ever unkind, we show a grown-up and handle it together: read it, report it, delete it.

5. When we remix, we say thank you in the Notes and Credits.

Signed: Leo ______   Mom ______

5.3

ScratchJr — Coding for Ages 5–7

17 min
By the end you can
  • Explain how ScratchJr differs from Scratch
  • Build a tap-to-talk pet with a recorded sound
  • Run a short, playful session with a 4–7-year-old
Key ideas
  • ScratchJr is a free tablet app (iPad, Android, Chromebook) with picture blocks, so no reading is needed.
  • Blocks snap into a row read left to right, like a sentence. Motion numbers count grid squares.
  • Six colors: yellow Triggering · blue Motion · purple Looks · green Sound · orange Control · red End. (Not the same as Scratch: trust the pictures.)
  • Up to four pages per project, turned with Go to Page. Projects stay on the device: no online community.
  • Coach in 10–15-minute sessions: story first, you read, they tap, lots of silly sounds.
Worked example — "My Pet Says Hi"
👆 Start on Tap ⤴️ Hop 2 🔼 Grow 2 🎙️ My Sound 🔽 Shrink 2 ⏹️ End

Tap the pet: it hops, puffs up, says hi in a real voice, and settles back down. Shrink matters: without it the pet grows bigger with every tap. It's the same thinking as your first Scratch cat (an event, a sequence, a sound), laid out sideways. A rough Scratch equivalent stacks top to bottom (a "hop" becomes up, then back down):

when this sprite clicked
change y by 20
change size by 20
play sound recording1 until done
change size by -20
change y by -20
Your turn — Build it on a tablet
  1. Open ScratchJr → house icon → big +. Tap + beside the characters and pick an animal.
  2. Yellow: drag Start on Tap. Blue: snap Hop on its right. Purple: Grow. Tap the pet to test.
  3. Green: tap the microphone, record "Hi! I'm your pet!", accept, and snap the sound on.
  4. Purple: Shrink. Red: End. Tap the pet.
  5. Stretch: add page 2 (+ in the page strip) and end page 1's green-flag script with Go to Page.

5.4

What Comes After Scratch

10 min
By the end you can
  • Place ScratchJr, Scratch, hardware and text code on one road map
  • Name what's still ahead inside Scratch (lists, extensions)
  • Explain why the jump to Python is mostly syntax
Key ideas
  • Road map: ScratchJr (5–7) → Scratch (8+) → deeper Scratch, physical computing, or text languages. There's no single correct path.
  • Still ahead in Scratch: lists (Variables → Make a List) and extensions via the Add Extension button, bottom-left: Pen, Music, Text to Speech, Video Sensing, micro:bit.
  • Beyond the screen: Makey Makey (7+), LEGO robotics (8+), micro:bit (9+).
  • The concepts transfer. Sequences, loops, conditionals, variables and events exist in every language.
  • Momentum comes from interest. One more exciting project beats rushing to the next tool.
Worked example — the same loop, two ways
repeat 3
say Hi! for 1 seconds
for i in range(3):
    print("Hi!")

Same loop, same count, same message. Your child already owns the idea; Python just types it.
