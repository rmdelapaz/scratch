⭐ Lesson 4.1: Clones — One Sprite, Many Copies

Welcome to Module 4! Real games are crowded — a sky full of raindrops, a swarm of enemies, a shower of stars. In this lesson you'll learn how one sprite can stamp out as many copies of itself as you need, and you'll build a sky of falling stars that becomes the heart of our capstone game.

📚 What You'll Learn

By the end of this lesson, you will be able to:

  • Explain what a clone is, using the rubber-stamp idea
  • Use the three clone blocks: create clone of myself, when I start as a clone, and delete this clone
  • Use the "hidden original makes clones in a forever loop" pattern
  • Know what a clone copies from the original — and why you must clean clones up
  • Coach your child through their first "many things at once" project

🎓 Learn It: Why one sprite isn't enough

Remember the apple game from Lesson 3.2? One apple fell at a time. That works, but it's a bit lonely. What if you wanted twenty apples raining down at once?

The obvious answer is to duplicate the apple sprite twenty times. Kids try this all the time, and it does work — right up until you want to change something. Make the apples fall faster, and now you're editing twenty sprites. Miss one and it behaves differently from the rest. Your sprite list becomes a mile long, and the project turns into a chore.

Clones fix this. A clone is a copy of a sprite that Scratch makes while the program is running. You write the code once, in one sprite, and that sprite makes as many copies as it needs — then throws them away when they're done.

Think of a rubber stamp. The stamp itself stays in your hand; you never see it on the paper. Each time you press it down, you get a print. Change the stamp, and every print after that changes too. In Scratch, the original sprite is the stamp, and clones are the prints.

🎓 Learn It: The three clone blocks

This two-script shape is the pattern you'll use for almost every clone project: the original hides and makes clones in a forever loop with a wait; each clone shows itself, does its job, and deletes itself. The wait matters — without it, the loop would make clones as fast as the computer can go and hit the limit in a split second.

🎓 Learn It: How clones behave

A handful of rules explain almost every clone surprise. Read them once now; you'll recognize them the moment something odd happens.

  • Each clone runs its own copy of the scripts. Twenty clones means twenty copies of the "when I start as a clone" script running side by side, each one minding its own business.
  • A clone starts exactly where the original is — same spot, same direction, same costume, same size, same color effect. That's why we move the original before stamping: wherever the stamp is, the print lands.
  • A clone copies "hidden" too. If the original is hidden, every clone is born hidden. That's why the clone script starts with show.
  • "when 🟩 clicked" runs only on the original. Clones are created after the flag is clicked, so they miss it. Put clone behavior under when I start as a clone.
  • Some hats run on everyone. Blocks like when I receive and when this sprite clicked run on the original and every clone. Handy later, surprising at first.
  • Scratch allows about 300 clones at once. After that, create clone quietly does nothing. Clones that fall off-screen but are never deleted still count, so the game slows down and new ones stop appearing. Always give each clone a way to delete this clone.
  • The red stop sign (or a new green flag) deletes every clone. You always get a clean slate.

🛠️ Try It: Build falling stars

Let's put the pattern to work. We'll make stars appear at random spots along the top of the stage and drift down to the bottom, one new star every second.

💡 Before you start

Start a new project. Hover over the cat face button in the bottom-right corner, click Choose a Sprite, and pick Star. Delete the cat if you like. A dark backdrop such as Stars or Night City makes the stars pop.

  1. Program the stamp (the original)

    With the Star selected, build this. The original hides, then forever: jumps to a random spot along the top, stamps a clone there, and waits a second.

    when ⚑ clicked
    hide
    forever
    go to x: pick random -220 to 220 y: 180
    create clone of myself
    wait 1 seconds

    Click the green flag now. Nothing visible happens — and that's correct! The clones are being made, but they're all hidden, like prints made with invisible ink.

  2. Program the prints (each clone)

    In the same Star sprite, start a second script. Each clone shows itself, falls until it's near the bottom, then deletes itself.

    when I start as a clone
    show
    repeat until ⟨ y position ⟩ < -170
    change y by -5
    delete this clone

    The less-than block is green (Operators); drop the blue y position reporter from the bottom of Motion into its left slot and type -170 on the right.

  3. Run it

    Click the green flag. Every second a new star appears somewhere along the top and glides down, while the earlier stars keep falling. Press stop and they all vanish at once.

🤔 Why not "until touching edge"?

It's tempting, but each star is born at the top of the stage — already touching the edge. It would delete itself instantly and you'd see nothing. Checking the y position means "stop when you're near the bottom," which is exactly what we want.

✅ Hold on to this project!

Save it (or File → Save to your computer). These falling stars are the heart of Star Catcher, the game you'll plan and build together in Lesson 4.3. There, a bowl will slide along the bottom, each clone will check "am I touching the bowl?" to score a point, and stars that reach the bottom will cost a life.

🛠️ Try It: Make it yours

Because every clone runs its own script, you can make each one a little different. Add these inside the clone script, right after show:

🎨 Easy

  • Change wait 1 to wait 0.3 — a meteor shower!
  • Change -5 to -2 for slow, dreamy stars.
  • Add turn ↻ 5 degrees inside the repeat so they spin as they fall.

🔥 A bit more

  • Random sizes: set size to (pick random 30 to 100) %.
  • Random colors: change color effect by (pick random 0 to 200).
  • Random speeds: make a For this sprite only variable called speed, set it to pick random -2 to -8, then change y by speed.
when I start as a clone
set size to pick random 30 to 100 %
change color effect by pick random 0 to 200
show
repeat until ⟨ y position ⟩ < -170
change y by -5
delete this clone
💡 Challenge: snow and bubbles

Snow: paint a small white circle sprite, make clones fall slowly, and add change x by (pick random -2 to 2) inside the loop so each flake drifts.

Bubbles: flip it upside down. Stamp clones along the bottom (y: -180), have each one change y by 3 until its y position is greater than 170, and add change ghost effect by 2 so they fade as they rise. Same pattern, opposite direction — proof that you've learned the idea, not just the recipe.

When clones misbehave, ask one question first: "Is this code running on the stamp, on the prints, or on both?" It solves most clone mysteries.

🌱 Growth mindset: confusion is the feeling of your brain stretching

Clones are the first idea in this course where lots of things happen at once, and it's normal for your head to feel a little crowded. That fuzzy feeling isn't a sign you've hit your limit — it's what learning something genuinely new feels like. Adults often hide that feeling from kids. Try the opposite: say out loud, "This part is tricky for me. Let's slow down and figure out which stars are doing what." Your child learns that "tricky" is something you work through, not something that means you're bad at it.

💬 Teach It: Stamps and prints

Clones are abstract. Your job is to make them physical before they become code.

Start with a real stamp

If you have a rubber stamp, a potato stamp, or even a cookie cutter and play-dough, use it. Stamp a few prints, then ask:

"Where's the stamp now? It's in my hand, not on the paper. In Scratch, the original star hides like the stamp, and all the stars you see falling are prints. What should each print do after it lands?"

Let them discover the "invisible ink" bug

When they first run the stamp script and see nothing, resist fixing it. Ask:

"We hid the stamp. The prints are copies of the stamp… so what do you think the prints look like right now?"

Working out that the clones are hidden too — and need a show — is a huge "aha," and far stickier than being told.

👧 Ages 5–7

Watching copies pop into existence feels like magic, and that's enough. Keep to the stamp analogy and skip the rules about limits. You build the scripts; they pick the sprite, the backdrop, and how fast the stars fall.

🧒 Ages 8–11

They can build both scripts with you nearby. Offer the random size and color challenge — seeing every star come out different shows that each clone runs its own copy of the code.

🧑 Ages 12+

Challenge them to spawn enemies: clones that come in from the right side and move toward the player, with a Game Over if one touches them. Ask them to explain why their clones get deleted, and what would happen if they didn't.

⚠️ Common kid bug

Kids often put create clone of myself inside the clone's own script. Each clone then makes another clone, which makes another… and the screen floods until it hits the 300 limit. It's a great teaching moment: "Who should be doing the stamping — the stamp or the prints?"

🎯 Quick Check

Question 1: The original star is hidden. You make clones, but none appear on the stage. Why?

Question 2: Which script runs only on the new clones, never on the original?

Question 3: Your falling-stars game gets slower and slower, and then new stars stop appearing. The most likely cause?

📓 Learning Journal

Take five minutes to write it down

Clones are a big step up. Writing it down now, while it's fresh, will make Lesson 4.3 much easier.

  1. Key concepts: In your own words, what's the difference between the original sprite and a clone? What does each of the three clone blocks do?
  2. What clicked: Was it the stamp idea? The moment the first star fell? Realizing why the clones were invisible?
  3. Questions & confusion: Which rule still feels slippery — what clones copy, which hats run where, or why deleting matters?
  4. Ideas to try: Something else that could come in crowds: fish, balloons, zombies, falling pizza? Sketch how the stamp and prints would work.
  5. Progress & feelings: How did it feel to manage many things at once? How did your child react when the sky filled with stars?

💡 Teach It tip: Have your child draw a big stamp with arrows pointing to lots of little stars, and label them "original" and "clones." Explaining that picture back to you is great proof they understand.

Summary & What's Next

🎓 Key Takeaways

  • A clone is a copy of a sprite made while the program runs — the original is the stamp, clones are the prints.
  • The pattern: the original hides and runs create clone of myself in a forever loop with a wait; each clone uses when I start as a clone to show, do its job, and delete this clone.
  • Clones start where the original is and copy its costume, size, effects, and visibility.
  • "when 🟩 clicked" runs only on the original. Scratch allows about 300 clones, so always delete the ones you're done with.

❓ Common Questions at This Stage

Is my child too young for clones?

Not for enjoying them. Young kids love watching copies appear and can happily choose the sprite and speed while you build. The deeper rules — what clones copy, why deletion matters — usually land around age 8 or 9. There's no rush.

Can a clone tell which copy it is?

Yes, with a variable made "For this sprite only." Each clone gets its own private copy of that variable, so you can give every clone its own speed or ID number. We touched on this in the random-speed challenge; it's a great next step for older kids.

Should we just duplicate sprites instead? It seems simpler.

For two or three characters that each behave differently, duplicating is perfectly fine. Clones win when you need many of the same thing, or an unknown number of them. If you catch yourself making Star4 and Star5, it's time for clones.
