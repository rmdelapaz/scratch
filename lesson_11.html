🧩 Lesson 4.2: My Blocks — Make Your Own Blocks

What if Scratch doesn't have the block you want? Make it yourself! In this lesson you'll bundle a chunk of code into a brand-new block with its own name, like jump or reset game. Programmers have a name for this, and it's one of the most useful ideas in coding.

📚 What You'll Learn

By the end of this lesson, you will be able to:

  • Explain why naming a chunk of code makes projects easier to read and reuse
  • Create a custom block with the My Blocks category and the Make a Block dialog
  • Attach steps to the define hat block and use your new block anywhere in that sprite
  • Add an input so one block can behave differently each time
  • Coach your child to spot repeated code and turn it into their own block

🎓 Learn It: Why make your own blocks?

As projects grow, the same few blocks keep showing up: a jump here, the same jump there, another copy for when the cat touches something. Long, repetitive scripts are hard to read, and changing the jump means hunting down every copy.

Think of a recipe card that says "Make pancakes." Those two words stand for a whole list of steps: crack the eggs, whisk, pour, flip. Once the card is written, you just say "make pancakes."

A custom block works the same way. You write the steps once, give them a name, and from then on one block stands for all of them. Programmers call a named chunk of code a function. Your child doesn't need the word, but you're doing exactly what professional coders do every day.

🎓 Learn It: The Make a Block dialog

Click the pink My Blocks circle at the bottom of the block categories, then the Make a Block button. A dialog opens with a pink block that says block name.

  1. Name your block

    Type a short action word that says what it does, like jump.

  2. Add an input (optional)

    Add an input (number or text) puts a slot in your block so you can hand it a value each time, like how many times to dance. You name the slot, for example times. (The boolean input is for yes/no values; skip it for now.)

  3. Add a label (optional)

    Add a label adds plain words between inputs so the block reads like a sentence, for example dance (times) times.

  4. Decide on "Run without screen refresh"

    Normally Scratch redraws the stage each time through a loop, so you watch things move. Tick this box and the whole block runs in one go, showing only the end result. Handy for setup, but animations happen instantly (you never see the jump!). Leave it unticked.

Click OK. Two things appear: your new block in the My Blocks palette, and a pink define hat block in the code area.

🎓 Learn It: The define block

The define block is your recipe card: whatever you snap underneath it is what your new block does. On its own it never runs; it waits until another script uses the block.

📝 The recipe (define)

define jump

The steps go under here.

🗣️ Using it (the call)

when ⚑ clicked
jump

Drag it from My Blocks like any other block.

Using the block is called calling it: the green flag script calls jump, Scratch runs the define script's steps, then comes back and carries on.

🛠️ Try It: Mini-project 1 — a jump block

Start a new project with the cat. Make a block named jump (no inputs, screen refresh unticked) and build this under the define hat:

define jump
repeat 10
change y by 10
repeat 10
change y by -10

Up ten little steps, down ten little steps. Now give the player a way to use it:

when space key pressed
jump

Press space and the cat hops. Now add a when this sprite clicked → jump script too: two ways to jump, one set of steps. Want a higher jump? Change the define script once, and both scripts get it.

🛠️ Try It: Mini-project 2 — add an input

An input lets one block do slightly different things. Click Make a Block, type dance, click Add an input (number or text) and name it times, then Add a label and type times. Click OK.

The new define block contains a round pink times oval: the input's value. Drag it out of the define block (you get a copy) into the repeat slot:

define dance times times
repeat times
turn ↻ 15 degrees
wait 0.2 seconds
turn ↺ 15 degrees
wait 0.2 seconds

Your palette block now has a white slot for any number:

when ⚑ clicked
dance 3 times
say Ta-da! for 1 seconds
dance 6 times

On the recipe card, the input is "how many pancakes?" Same steps, different number.

💡 Challenge: make jump (height)

Right-click the define block → Edit and add a number input called height. Use the Operators block (height / 10) as the "change y by" amount going up, and (0 − (height / 10)) going down. Now jump (50) is a hop and jump (150) a leap.

🛠️ Try It: A reset game block

Some of the most useful blocks simply tidy up. Every game puts things back to the start when the green flag is pressed, and that setup list gets long. Wrap it in a block called reset game:

define reset game
set score to 0
set lives to 3
go to x: 0 y: -150
show
when ⚑ clicked
reset game

(Make the score and lives variables first, as in Lesson 3.2.) Now the green flag script reads like plain English.

💡 My Blocks belong to one sprite

A custom block only appears in the palette of the sprite you made it in. To reuse it, drag the define script onto the other sprite's picture in the sprite list; it copies over.

🌱 Growth mindset: going back isn't going backward

Cleaning up code that already works can feel like admitting the first version was "wrong." It isn't. Programmers call it refactoring and do it constantly, because every project teaches a better way. When your child spots a repeated chunk in an old game, say: "Look how much you've grown — you can see things now you couldn't last month." Then say the same about your own projects.

💬 Teach It: New words for the computer

For kids, the big idea isn't "functions." It's that they invent new words and the computer learns them.

Start with a game of "new word"

Before touching the computer, play it out loud:

"I'm going to teach you a new word: zoomba. Zoomba means clap twice and spin around. Ready? Zoomba! …Now let's teach the computer a new word."

Let them find the repeats

When the same blocks appear twice, don't point it out. Ask:

"I see those same blocks twice. What would you call what they do? What if that were one block with that name?"

The name is theirs ("boing" is perfect; silly names stick), and so is the number: let them try dance 1, dance 20, dance 100.

👧 Ages 5–7

"Teaching the computer a new word." Build the define script together; they pick the name and use the block. Skip inputs.

🧒 Ages 8–11

They can build jump and dance alone. Introduce inputs with dance (times), then challenge them to invent a block like sneeze or celebrate.

🧑 Ages 12+

Have them refactor their Lesson 3.2 game, replacing setup and repeated chunks with named blocks, then explain why it's easier to change.

⚠️ Common kid bug

They type "times" into a slot instead of dragging the oval out, so Scratch sees the word, not the number. Point at the pink oval: "The value lives in here — drag it out."

🎯 Quick Check

Question 1: Where do you put the steps that your new block should do?

Question 2: Your jump block works, but the cat seems to teleport instead of hopping. What's the likely cause?

Question 3: You made a reset game block on the Bowl sprite, but it's missing when you click the Star sprite. Why?

📓 Learning Journal

Take five minutes to write it down

A notebook or notes app works. Writing things down helps them stick, and lets you look back and see how far you've come.

  1. Key concepts: In your own words, what's the difference between the define block and using it? What does an input add?
  2. What clicked: The recipe card, two scripts sharing one jump, or dance 3 becoming dance 6?
  3. Questions & confusion: Is dragging the input oval still fuzzy? Screen refresh? Note exactly where you got stuck.
  4. Ideas to try: Name one block you wish Scratch had. Could you build it now?
  5. Progress & feelings: How does it feel to make blocks instead of just using them? What did your child name their first one?

💡 Teach It tip: Have your child start a "dictionary" page: each block they invent, with its name and a drawing of what it does.

Summary & What's Next

🎓 Key Takeaways

  • A custom block (a function) names a chunk of code so you write it once.
  • Make a Block sets the name, inputs, and labels; leave Run without screen refresh unticked.
  • Steps go under the define hat; drag the input oval out of it to use its value.
  • My Blocks belong to one sprite; drag the define script to share it.

❓ Common Questions at This Stage

Is this too advanced for my 6-year-old?

Not the idea: young kids get "teaching the computer a new word" right away. Skip inputs, build the define script together, and let them enjoy using the block they named.

When should we make a custom block instead of just copying blocks?

If you've copied the same group of blocks twice, or a script no longer fits on screen, give that chunk a name. There's no penalty for doing it later.

I renamed my block and now things look different. Did I break something?

Probably not. When you edit a block, Scratch updates every place it's used automatically, which copied blocks can't do.
