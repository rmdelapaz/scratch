🧩 Lesson 4.2: My Blocks — Make Your Own Blocks

What if Scratch doesn't have the block you want? Make it yourself! In this lesson you'll bundle a chunk of code into a brand-new block with its own name, like jump or reset game. Programmers have a name for this, and it's one of the most useful ideas in coding.

📚 What You'll Learn

By the end of this lesson, you will be able to:

  • Explain why naming a chunk of code makes projects easier to read and reuse
  • Create a custom block with the My Blocks category and the Make a Block dialog
  • Attach steps to the define hat block and use your new block anywhere in that sprite
  • Add an input so one block can behave differently each time
  • Coach your child to spot repeated code and turn it into their own block

Estimated Time: 35 minutes  •  Project: a jump block, a dance (times) block, and a reset game block

🎓 Learn It: Why make your own blocks?

By now your projects are getting bigger. You've probably noticed that scripts grow long, and that the same little group of blocks shows up again and again: a jump here, the same jump there, another copy for when the cat touches something. Long, repetitive scripts are hard to read, and when you want to change the jump you have to hunt down every copy.

Think of a recipe card that says "Make pancakes." Those two words stand for a whole list of steps: crack the eggs, whisk, pour, flip. Once the card is written, you just say "make pancakes" and everybody knows what to do.

A custom block works the same way. You write the steps once, give them a name, and from then on one block stands for all of them. It's like teaching a dog a new trick: you practice the steps together, then you only have to say "roll over."

Programmers call a named chunk of code a function (or sometimes a procedure). You don't need to use those words with your child, but it's nice to know that when you make a block in Scratch, you're doing exactly what professional coders do in Python or JavaScript every day.

Three different scripts each say "jump," but the actual jumping steps exist in only one place. Change them there, and every jump changes at once.

🎓 Learn It: The Make a Block dialog

Scroll to the bottom of the block categories and click the pink My Blocks circle. It starts nearly empty except for one button: Make a Block. Click it and a dialog box opens with a pink block in the middle that says block name.

  1. Name your block

    Click in the pink block and type a name that says what it does, like jump. A good name is short and uses an action word.

  2. Add an input (optional)

    Below the block are three buttons. Add an input (number or text) puts a slot in your block so you can hand it a value each time you use it, like how many times to dance. You'll name the slot, for example times. (The second input button, boolean, is for yes/no values. You can skip it for now.)

  3. Add a label (optional)

    Add a label adds plain words between inputs so the block reads like a sentence, for example dance (times) times.

  4. Decide on "Run without screen refresh"

    Normally Scratch pauses to redraw the stage each time through a loop, which is how you get to watch things move. Tick this box and Scratch runs the whole block in one go and only shows the end result. That's handy for quick setup work, but it makes animations happen instantly (you never see the jump!). Leave it unticked unless you have a reason.

Click OK. Two things appear: your new block in the My Blocks palette, and a pink define hat block in the code area.

🎓 Learn It: The define block

The define block is your recipe card. Whatever you snap underneath it is what your new block does. On its own, a define script never runs; it waits until some other script uses the block.

📝 The recipe (define)

define jump

The steps go under here.

🗣️ Using it (the call)

when ⚑ clicked
jump

Drag it from My Blocks like any other block.

Programmers call using the block calling it: the green flag script "calls" jump, Scratch jumps over to the define script, runs its steps, then comes back and carries on.

🛠️ Try It: Mini-project 1 — a jump block

Start a new project (or use the cat from earlier lessons). Make a block named jump with no inputs and screen refresh left unticked. Then build this under the define hat:

define jump
repeat 10
change y by 10
repeat 10
change y by -10

Up ten little steps, down ten little steps. Now give the player a way to use it:

when space key pressed
jump

Press the space bar and the cat hops. Here's the payoff: add a when this sprite clicked → jump script too. Two ways to jump, one set of jumping steps. Want a higher jump? Change the define script once, and both scripts get the new jump.

🛠️ Try It: Mini-project 2 — add an input

An input lets the same block do slightly different things. Click Make a Block, type dance, click Add an input (number or text) and name it times, then click Add a label and type times. Click OK.

Look closely at the new define block: it contains a round pink times oval. That oval is the input's value. Drag it out of the define block (you'll get a copy) and drop it into the repeat slot:

define dance times times
repeat times
turn ↻ 15 degrees
wait 0.2 seconds
turn ↺ 15 degrees
wait 0.2 seconds

Now the block in your palette has a white slot. Type any number when you use it:

when ⚑ clicked
dance 3 times
say Ta-da! for 1 seconds
dance 6 times

Back in the recipe analogy, the input is "how many pancakes?" The steps stay the same; the number changes.

💡 Challenge: make jump (height)

Edit your jump block (right-click the define block → Edit) and add a number input called height. Inside, use the green Operators block (height / 10) as the "change y by" amount going up, and (0 − (height / 10)) going down. Now jump (50) is a small hop and jump (150) is a leap.

🛠️ Try It: A reset game block

Custom blocks aren't only for actions. Some of the most useful ones simply tidy up. Every game needs to put things back to the start when you press the green flag, and that setup list gets long. Wrap it in a block called reset game:

define reset game
set score to 0
set lives to 3
go to x: 0 y: -150
show
when ⚑ clicked
reset game

(You'll need to make the score and lives variables first, as in Lesson 3.2.) Now the green flag script reads like plain English. Anyone can glance at it and know what happens first.

⭐ You'll use this in the capstone

In Lesson 4.3 you and your child build Star Catcher: a bowl slides along the bottom catching falling stars (made with the clones from Lesson 4.1). The bowl's reset game block is exactly this one. Keep this project handy!

💡 My Blocks belong to one sprite

A custom block only shows up in the palette of the sprite you made it in. Click a different sprite and it's gone. To reuse it, drag the define script onto the other sprite's picture in the sprite list (it copies), and the block appears there too.

🌱 Growth mindset: going back isn't going backward

Cleaning up code that already works can feel like wasted effort, or like admitting the first version was "wrong." It isn't. Professional programmers call this refactoring, and they do it constantly, because every project teaches you a better way to write the next one. When your child reopens an old game and spots a repeated chunk, say it out loud: "Look how much you've grown — you can see things now you couldn't see last month." And let them hear you say the same about your own projects.

💬 Teach It: New words for the computer

For kids, the big idea isn't "functions." It's that they get to invent new words and the computer learns them. That's powerful, and they can feel it.

Start with a game of "new word"

Before touching the computer, play it out loud:

"I'm going to teach you a new word: zoomba. Zoomba means clap twice and spin around. Ready? Zoomba! …Now let's teach the computer a new word."

Let them find the repeats

When a script has the same group of blocks in two places, don't point it out. Ask:

"I see those same blocks twice. What would you call what they do? What if that were one block with that name?"

  • The name is theirs. "boing" instead of "jump" is perfect. Silly names get remembered.
  • The number is theirs. With an input, let them try dance 1, dance 20, dance 100 and see what happens.

👧 Ages 5–7

Frame it as "teaching the computer a new word." You build the define script together; they choose the name and use the new block from the palette. Skip inputs for now.

🧒 Ages 8–11

They can build jump and dance on their own. Introduce inputs with dance (times), and challenge them to invent a block for their own sprite, like sneeze or celebrate.

🧑 Ages 12+

Have them refactor their Lesson 3.2 game: find the setup and repeated chunks and replace them with named blocks. Ask them to explain why the new version is easier to change.

⚠️ Common kid bug

They type the input's name into a slot instead of dragging the oval out of the define block, so Scratch sees the word "times," not the number. Point at the pink oval: "The value lives in here — drag it out."

🎯 Quick Check

Question 1: Where do you put the steps that your new block should do?

Question 2: Your jump block works, but the cat seems to teleport instead of hopping. What's the likely cause?

Question 3: You made a reset game block on the Bowl sprite, but it's missing when you click the Star sprite. Why?

📓 Learning Journal

Take five minutes to write it down

A notebook, a notes app, or the back of an envelope — anything works. Writing things down helps them stick, and later you'll be able to look back and see how far you've come.

  1. Key concepts: In your own words, what's the difference between the define block and using the block? What does an input add?
  2. What clicked: Was it the recipe-card idea, seeing two scripts share one jump, or watching dance 3 turn into dance 6 with one number?
  3. Questions & confusion: Is dragging the input oval out of the define block still fuzzy? Screen refresh? Write down exactly where you got stuck.
  4. Ideas to try: Name one block you wish Scratch had. Could you build it now as a custom block?
  5. Progress & feelings: How does it feel to be making blocks instead of just using them? What name did your child pick for their first block?

💡 Teach It tip: Have your child start a "dictionary" page in their coder's notebook: each custom block they invent, with its name and a drawing of what it does.

Summary & What's Next

🎓 Key Takeaways

  • A custom block names a chunk of code so you write it once and use it anywhere; programmers call this a function.
  • My Blocks → Make a Block lets you choose a name, inputs, and labels; leave Run without screen refresh unticked for animations.
  • The steps go under the define hat; drag the input oval out of the define block to use its value.
  • My Blocks belong to one sprite; drag the define script onto another sprite to share it.

❓ Common Questions at This Stage

Is this too advanced for my 6-year-old?

Not the idea. Young kids understand "teaching the computer a new word" right away. Skip inputs and screen refresh, build the define script together, and let them enjoy using the block they named.

When should we make a custom block instead of just copying blocks?

A good rule of thumb: if you've copied the same group of blocks twice, or a script is too long to see on screen, give that chunk a name. But there's no penalty for waiting — you can always turn working code into a block later.

I renamed my block and now things look different. Did I break something?

Probably not. When you edit a block (right-click the define block → Edit), Scratch updates every place it's used automatically. That's one of the big advantages over copied blocks, which you'd have to fix one by one.
